**Step 2: Create ChangeTrackingService** `src/main/services/changeTrackingService.ts`

Class with these members:
- `private accumulators: Map<string, { files: Set<string>; timer: ReturnType<typeof setTimeout> | null }>` keyed by `repoPath:level`
- `private readonly debounceMs: number` (default 1000)
- `private storage: C4StorageService`
- Constructor takes `(storage: C4StorageService, debounceMs = 1000)`

Public methods:
- `recordChange(repoPath: string, level: C4Level, changedPath: string): void` — Adds `changedPath` to the accumulator for `repoPath:level`. Resets the debounce timer. On timer fire, calls `flush()`.
- `shutdown(): void` — Clears all pending timers and accumulator map. Called on app quit.

Private methods:
- `flush(repoPath: string, level: C4Level, key: string): void` — Takes accumulated files, maps to elements, propagates up, persists to DB, updates state, emits IPC. **CRITICAL: Before calling `storage.updateState(repoPath, level, 'stale')`, check `storage.getState(repoPath, level)`. If state is `'generating'`, skip the state update but still persist change tracking and emit event.** This prevents overwriting the generating state (see research Pitfall 2).
- `mapFilesToElements(repoPath: string, level: C4Level, files: string[]): AffectedElement[]` — Path-based heuristic mapping:
  - **code level**: element = filename without extension. `elementId = sanitizeId(fileName)`, `elementName = fileName`.
  - **component level**: extract directory segment after container root (`main` or `renderer`). Capitalize first letter. `elementId = sanitizeId(capitalizedName)`, `elementName = capitalizedName`.
  - **container level**: if path includes `/main/` → `elementId = 'Main_Process'`, `elementName = 'Main Process'`. If includes `/renderer/` → `elementId = 'Renderer_Process'`, `elementName = 'Renderer Process'`.
  - **context level**: return empty array (context level excluded from element mapping per CHNG-02).
  - Deduplicate by `elementId` using a `Set<string>`.
- `propagateUp(direct: AffectedElement[]): AffectedElement[]` — For each direct element, create propagated entries for parent levels. Code → Component + Container. Component → Container. Container → nothing more. Propagated entries have `isDirect: false`. Deduplicate: if an element already exists as `isDirect: true`, don't add a duplicate `isDirect: false`.
- `emitChangeEvent(repoPath: string, level: C4Level, files: string[], elements: AffectedElement[]): void` — Broadcasts `c4-storage:state-changed` to all windows with enriched payload including `changedFiles` and `affectedElements` fields. Uses `BrowserWindow.getAllWindows()`.
- `computeElementCounts(elements: AffectedElement[]): Record<string, number>` — Counts direct elements per level. Returns e.g. `{ container: 1, component: 2, code: 5 }`.

Standalone utility (exported):
- `sanitizeId(name: string): string` — Replicates `C4PlantUMLGenerator.sanitizeId` exactly: `name.replace(/[^a-zA-Z0-9_]/g, '_').replace(/^[0-9]/, '_$&')`.

**Path normalization**: Always normalize `changedPath` with `.replace(/\\/g, '/')` before storing or comparing (Pitfall 3 from research).

**Step 1: Add `diagram_change_tracking` table to C4StorageService schema**

In the `constructor` method of `C4StorageService`, after the existing `CREATE TABLE IF NOT EXISTS diagram_storage` statement, add:

```sql
CREATE TABLE IF NOT EXISTS diagram_change_tracking (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  repo_path TEXT NOT NULL,
  level TEXT NOT NULL CHECK(level IN ('context','container','component','code')),
  changed_files TEXT NOT NULL,
  affected_elements TEXT NOT NULL,
  element_counts TEXT NOT NULL,
  recorded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(repo_path, level)
);

CREATE INDEX IF NOT EXISTS idx_change_tracking_repo
  ON diagram_change_tracking(repo_path);
```

The `UNIQUE(repo_path, level)` constraint enables `INSERT OR REPLACE` upsert semantics — only the most recent change snapshot is kept per `(repo_path, level)`.

**Step 2: Add three new public methods to C4StorageService**

`upsertChangeTracking(repoPath: string, level: C4Level, changedFiles: string[], affectedElements: AffectedElement[], elementCounts: Record<string, number>): void`
- Uses `INSERT OR REPLACE INTO diagram_change_tracking` with `this.normalizePath(repoPath)`.
- Stores `changedFiles` as `JSON.stringify(changedFiles)`, `affectedElements` as `JSON.stringify(affectedElements)`, `elementCounts` as `JSON.stringify(elementCounts)`.

`getChangeTracking(repoPath: string, level: C4Level): { changedFiles: string[]; affectedElements: AffectedElement[]; elementCounts: Record<string, number> } | null`
- SELECT from `diagram_change_tracking` WHERE `repo_path = ? AND level = ?`.
- Parse JSON fields back. Return null if no row found.

`clearChangeTracking(repoPath: string, level: C4Level): void`
- DELETE from `diagram_change_tracking` WHERE `repo_path = ? AND level = ?`.
- Called when state transitions to `fresh` or `generating` (the caller handles this logic; this method just deletes).

Import `AffectedElement` from `'../../../shared/types/changeTracking'`.
