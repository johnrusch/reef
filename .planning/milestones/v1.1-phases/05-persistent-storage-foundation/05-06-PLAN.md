**Part B: Subscribe to state changes from main process in VisualMapTab**

The `onStateChanged` subscription currently exists in DiagramViewer.tsx (lines 260-271) but VisualMapTab needs it too for the pre-DiagramViewer rendering path. Without this subscription, the Zustand store won't update when the backend broadcasts state changes (like 'generating' -> 'fresh'), and the VisualMapTab won't re-render.

Add a useEffect subscription after the existing `loadPersistedDiagram` effect (after line 106):

```typescript
// Subscribe to state changes from main process (needed for pre-DiagramViewer states)
useEffect(() => {
  if (!repository) return;

  const { setState } = useDiagramStateStore.getState();
  const unsubscribe = window.reef.c4Storage.onStateChanged((_, data) => {
    if (data.repoPath === repository.path) {
      setState(data.repoPath, data.level, data.state, data.elementId, data.errorMessage);
    }
  });

  return unsubscribe;
}, [repository]);
```

This ensures that when the backend transitions state to 'generating' (from the generateDiagram call), the Zustand store updates, which triggers a re-render of VisualMapTab, which now shows the generating indicator.

**Why this fixes both gaps:**
- Gap 1 (GeneratePromptCard): The GeneratePromptCard is now rendered from the default render path (after the DiagramViewer check fails), not inside a `viewMode === 'diagram'` guard. When a user opens Visual Map tab for a repo with no stored diagram, currentState is 'never_generated', diagram is '', so the GeneratePromptCard shows.
- Gap 2 (Generating badge): When the user clicks Generate on the GeneratePromptCard, generateDiagram() runs, calls updateState('generating'), the backend broadcasts the state change, the onStateChanged subscription updates the Zustand store, VisualMapTab re-renders, and now hits the `currentState === 'generating' && !diagram` condition, showing the standalone generating indicator with the blue spinner badge.
