### New Integration Finding

**handleRegenerateFromBadge missing IPC state transitions (MEDIUM)**

**File:** `DiagramViewer.tsx` lines 155-168
**From:** DiagramStateBadge `onRegenerate` click (NAVG-01 badge-click path)
**To:** diagramStateStore / c4-storage:state-changed pipeline

`handleRegenerateFromBadge` calls `onRegenerateDiagram` directly without calling `window.reef.c4Storage.updateState()`. Compare to `handleRegenerate` (lines 121-153) which correctly calls `updateState('generating')` before and `updateState('fresh')` after.

**Impact:** When clicking the amber "Outdated" DiagramStateBadge, regeneration completes but the badge doesn't visually transition through generating (spinner) → fresh (green). The legacy `StalenessBadge` (local `isStale` state) correctly disappears. The Zustand-driven `DiagramStateBadge` remains stale until the user navigates away and back.

**Affected requirements:** NAVG-01 (functional requirement met — regeneration works), STOR-04 (state tracking incomplete for this path)

## E2E Flow Verification

### Flow 1: Add Repo → Auto-Generate → Badge Updates (COMPLETE)

```
AddRepositoryModal.handleAddRepository()
  → checks autoGenerateOnRepoAdd preference
  → GenerationPromptModal or auto-generate path
  → addJob() + window.reef.c4Generation.enqueue()
  → generationQueueService broadcasts c4-generation:progress
  → MainLayout.onProgress → generationQueueStore.setProgress() → GenerationStatusBar
  → generationQueueService: getStorageService().updateState('generating') + broadcastToAll('c4-storage:state-changed')
  → DiagramViewer.onStateChanged → setState('generating') → DiagramStateBadge spinner
  → generationQueueService: getStorageService().updateState('fresh') + broadcastToAll('c4-storage:state-changed')
  → DiagramViewer.onStateChanged → setState('fresh') → DiagramStateBadge green check
  → generationQueueService broadcasts c4-generation:complete
  → MainLayout.onComplete → ToastContainer success toast
```

**Status: PASS** (Phase 10 resolved the background generation state transition gap)

### Flow 2: Diagram Persistence Across Restart (COMPLETE)

```
C4AnalyzerService.generateC4Diagram()
  → getStorageService().storeDiagram() → diagram_storage.db (SQLite)
  → App quit: cleanupC4Storage() closes SQLite
  → App reopen: registerC4StorageHandlers() initializes singleton
  → VisualMapTab → window.reef.c4Storage.getRepoStates() → loadStatesFromBackend()
  → DiagramStateBadge renders from Zustand store
```

**Status: PASS**

### Flow 3: File Change → Change Tracking → Visualization (COMPLETE)

```
chokidar detects file change (directory paths, no globs)
  → FileWatcherService: isRelevantFile() filter → handleFileChange()
  → ChangeTrackingService.recordChange() → 1000ms debounce
  → flush(): mapFilesToElements() + propagateUp() → affectedElements
  → storage.upsertChangeTracking() + storage.updateState('stale')
  → emitChangeEvent(): c4-storage:state-changed with changedFiles + affectedElements
  → DiagramViewer.onStateChanged → setState('stale') + setAffectedElements() + setChangedFiles()
  → DiagramPanel: DiagramStateBadge amber + ChangeBadge with file list
  → PlantUMLRenderer.applyChangeHighlighting(): amber fill (direct) / dashed border (inherited)
```

**Status: PASS**

### Flow 4: Click Changed Element → Navigate to Diff → Back (COMPLETE)

```
PlantUMLRenderer SVG click → DiagramViewer.handleElementClick(elementId)
  → isChangedElement check (directChangedIds or inheritedChangedIds)
  → handleNavigateToDiff: setIntent({targetFile, returnStack, returnLevel})
  → setActiveTab('commit')
  → CommitWorkflowTab: useEffect consumes intent → setHighlightedFile + handleViewDiff
  → EnhancedChangesPanel: amber ring highlight + useRef auto-scroll
  → DiffViewer: blue "Navigated from Visual Map" banner with back button
  → User clicks "Back to diagram" → restoreStack() → setActiveTab('visualmap')
```

**Status: PASS**
