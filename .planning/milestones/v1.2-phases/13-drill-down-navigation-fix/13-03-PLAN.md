<diagnosis>
Root cause from UAT diagnosis:

1. VisualMapTab.generateDiagram options type (lines 234-239) OMITS elementId:
   ```typescript
   const generateDiagram = async (options?: {
     type?: DiagramType;
     detailLevel?: DetailLevel;
     focusArea?: FocusArea;
     model?: ModelType;
     // elementId is MISSING here
   }) => {
   ```

2. Line 288 passes local React state `elementId` (from useState on line 30):
   ```typescript
   elementId: elementId,  // This is the React state variable, NOT options.elementId
   ```

3. useEffect on lines 41-46 resets local elementId to undefined when diagramType changes:
   ```typescript
   useEffect(() => {
     if (diagramType === 'c4-context' || diagramType === 'c4-container') {
       setElementId(undefined);
     }
   }, [diagramType]);
   ```

4. During drill-down, DiagramViewer calls handleControlChange({type: 'c4-component'}) then
   onRegenerateDiagram({...currentOptions, type: 'c4-component', elementId: 'some_container'}).
   The useEffect does NOT fire for c4-component, but the function never reads options.elementId
   anyway -- it always reads the stale local state variable.

Fix: Add elementId to options type. Use options?.elementId ?? elementId on line 288.
Also sync local state: call setElementId(options.elementId) so subsequent operations
(like state tracking and persisted diagram loading) use the correct value.
</diagnosis>
