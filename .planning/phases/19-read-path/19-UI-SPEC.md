## Component Inventory

Phase 19 introduces no new UI primitives. It extends existing flows and notification patterns.

### Modified Components

| Component | Change | Visual Contract |
|-----------|--------|-----------------|
| `AddRepositoryModal` | Insert `.reef/` detection branch before `autoGenerateOnRepoAdd` check | No visible change to modal layout — modal closes at same point in flow |
| `ToastContainer` / `useToastStore` | Two new toast messages for import states | Use existing `info` type (blue border, Info icon) |

### New Toast States

Two toast messages are introduced. Both use type `info` (blue border, `Info` icon, `text-blue-400`).

| State | Message | Duration |
|-------|---------|----------|
| Complete import | `Loaded diagrams from .reef/` | 4000ms (auto-dismiss) |
| Partial import | `Loaded {N} diagram{s} from .reef/ — generating {M} missing level{s}...` | 6000ms (auto-dismiss, longer because it describes ongoing background work) |

No new modal, dialog, or panel components are introduced in Phase 19. The generation prompt modal (`GenerationPromptModal`) is skipped entirely when `.reef/` has complete diagrams — it is not modified.

## Interaction States

### AddRepositoryModal — Extended Flow

```
User selects repository
    └── [existing] validate git repo
    └── [NEW] check for .reef/ folder
         ├── .reef/ with all SVGs present
         │     └── add to SQLite → populate LRU cache → close modal
         │           → toast: "Loaded diagrams from .reef/"
         │           (GenerationPromptModal is SKIPPED)
         ├── .reef/ with partial SVGs
         │     └── import available → close modal
         │           → toast: "Loaded N diagrams from .reef/ — generating M missing levels..."
         │           → background: enqueue missing levels via generationQueueService
         └── .reef/ absent, empty, or all-invalid
               └── [existing] fall through to autoGenerateOnRepoAdd check
                     └── [existing] prompt / auto-generate / skip behavior unchanged
```

The modal's loading state uses the existing `Loader2` spinner with text `Adding...` — no new loading state text is needed. The `.reef/` detection is non-blocking from the user's perspective: modal closes at the same moment it does today.

### Diagram Viewer — No Visual Change

Per decision D-08 (CONTEXT.md): there is no visual distinction between imported `.reef/` diagrams and freshly generated diagrams in the sidebar or viewer. The `VisualMapTab` SVG fast path already handles this — it reads from SQLite/LRU cache regardless of origin.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (modal) | "Add Repository" (unchanged — source: `AddRepositoryModal.tsx`) |
| Toast — complete import | "Loaded diagrams from .reef/" |
| Toast — partial import | "Loaded {N} diagram{s} from .reef/ — generating {M} missing level{s}..." |
| Toast — no change / fallthrough | no toast (silent fallthrough to existing flow) |
| Empty state (no .reef/) | Unchanged — existing `GeneratePromptCard`: "No C4 Diagrams Yet" |
| Error state — .reef/ corrupt/invalid | Silent fallthrough to generation prompt (no error toast to user; treat as if .reef/ absent per D-11) |
| Error state — import failure | No user-visible error; log to console and fall through to generation prompt (non-fatal per D-11) |

**Destructive actions in Phase 19:** None. No deletions, overwrites, or irreversible operations are surfaced to the user in the read path.

**Copywriting notes:**
- Use plural forms dynamically: "1 diagram" / "3 diagrams", "1 missing level" / "2 missing levels"
- Toast messages are sentence case, no trailing period
- "diagrams from .reef/" uses the literal folder name `.reef/` with backtick-style rendering not required — plain text is sufficient

**Source:** D-09, D-10, D-11 from `19-CONTEXT.md`.
