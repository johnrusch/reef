  <action>
Fix better-sqlite3 ABI mismatch for Electron 38.8.2 (requires NODE_MODULE_VERSION 139):

**Root cause analysis:**
- better-sqlite3 is a native module compiled against system Node.js v22 (ABI 127)
- Electron 38.8.2 uses Node.js v23.x internally (requires ABI 139)
- Native modules must be rebuilt to match Electron's Node.js version
- Current symptom: API key re-prompt due to cache service initialization failure

**Install electron-rebuild:**
```bash
npm install --save-dev electron-rebuild
```

**Update postinstall script in package.json:**
- Current: `"postinstall": "node scripts/update-plantuml.js"`
- New: `"postinstall": "node scripts/update-plantuml.js && electron-rebuild -f -w better-sqlite3"`
- Flags: `-f` (force rebuild), `-w better-sqlite3` (target specific module)

**Run initial rebuild:**
```bash
npx electron-rebuild -f -w better-sqlite3
```

**Verify native module:**
```bash
npm run start
# App should start without better-sqlite3 ABI errors
# C4 cache service should initialize successfully
# API key should not re-prompt after initial configuration
```

**Why electron-rebuild:**
- Official Electron solution for native module compatibility
- Automatically detects Electron version and compiles for correct ABI
- Only rebuilds specified modules (faster than rebuilding all)
- Integrates with npm postinstall for automatic rebuilds after dependency updates

**Alternative considered and rejected:**
- Rebuilding during electron-builder (too late, dev experience broken)
- Using @electron/rebuild (electron-rebuild is the canonical package)
- Prebuilt binaries (better-sqlite3 doesn't ship Electron builds for ABI 139)
